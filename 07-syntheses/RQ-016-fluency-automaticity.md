# RQ-016 — Fluency and automaticity

## Decision summary

Nếp should develop fluency only **after enough form/meaning knowledge exists to practice successfully**. Fluency practice should make useful language easier and more efficient to access, but every apparent speed gain must remain subordinate to:

```text
meaning / task success
+ acceptable accuracy
+ changed-context transfer
+ delayed retention
```

The core progression is:

```text
accurate/understood use
→ short focused repetition
→ reduced processing friction
→ vary content while preserving useful procedure
→ space practice
→ changed-task use
→ delayed changed-task use
```

Never use:

```text
faster practiced response
→ mastery
```

as an inference.

## Three levels of fluency evidence

Nếp should distinguish:

### 1. Cognitive/processing fluency
How efficiently relevant language knowledge can be retrieved/encoded.

Candidate evidence:
- lexical retrieval latency;
- construction processing latency;
- stability/variability of processing;
- successful response under reasonable time demand.

### 2. Utterance/performance fluency
Observable timing in speech/reading/writing/interaction.

Speaking examples:
- articulation/speech rate;
- pause frequency/location/duration;
- length of run;
- self-repetition/reformulation.

### 3. Perceived fluency
A listener's impression that production flows smoothly.

These are related but not interchangeable (`SRC-0169`, `SRC-0170`, `SRC-0177`).

## Fluency is multidimensional

Meta-analytic evidence shows that speed, productivity, breakdown and repair fluency relate differently to proficiency (`SRC-0169`). Listener judgments also weight speed and pausing differently from repair (`SRC-0170`).

Therefore Nếp must not create:

```text
fluency = words_per_minute
```

or:

```text
fluency = no pauses
```

A useful system observes multiple dimensions and interprets them relative to meaning, accuracy, task and learner history.

## Personal/L1 speaking style is a confound

`SRC-0171` shows that L1 and L2 temporal fluency are related. Some learners naturally pause more or speak faster in both languages.

Therefore a universal raw-speed threshold can unfairly classify normal personal speaking style as poor English.

Prefer:

```text
within-learner development
+ task-matched comparisons
+ human comprehensibility/intelligibility where needed
```

over ranking every learner against one absolute speaking rate.

The product may eventually use normalized/reference ranges, but they must not become mastery rules without validation.

## Automaticity needs converging evidence

Skill-acquisition work (`SRC-0173`) and later automaticity studies (`SRC-0177`, `SRC-0178`) support the idea that practice can make linguistic processing faster and more stable.

But fast incorrect responding is not useful automaticity.

Candidate automaticity evidence:

```text
correct / meaningful performance
+ faster or less effortful access over time
+ stable processing
+ transfer to a new item/context
+ retention after delay
```

Nếp should never infer automaticity from reaction time alone.

## Readiness before fluency practice

Fluency practice is not a substitute for learning unknown language.

Before deliberate fluency work on a target, learner evidence should indicate some combination of:
- meaning understood;
- form recognized;
- target recalled at least under moderate support;
- task is within vocabulary/construction readiness;
- errors are not so frequent that repetition would rehearse an unstable/wrong pattern.

If the learner repeatedly fails meaning/form, return to learning/retrieval—not more speed pressure.

Candidate gate:

```text
KNOW enough
→ PRACTICE easier access
```

rather than:

```text
DON'T KNOW
→ force faster guessing
```

Exact readiness thresholds remain experimental.

## Repetition works partly by reducing task-processing load

Task-repetition research (`SRC-0058`, `SRC-0172`, `SRC-0175`, `SRC-0176`) shows that repeated performance can improve observable fluency.

Mechanisms can include:
- content familiarity;
- conceptualization reuse;
- lexical/syntactic priming;
- repeated constructions;
- proceduralization.

This is why same-task repetition is useful—but also why it can overstate general learning.

Nếp must store:

```text
same_item_repetition_count
same_content_repetition_count
task_type_repetition_count
```

and never compare repetition #4 with unseen attempt #1 as if they were equivalent contexts.

## Same-task repetition → varied procedural repetition

Candidate practice ladder:

```text
1. first meaningful performance
2. repeat same content briefly
3. repeat with reduced support
4. preserve task/function but change content
5. change surface wording/partner/context
6. return after delay
```

Same-task repetition can help stabilize production. Variation is then needed to test and encourage portability.

This is compatible with findings showing both concentrated/blocked and varied/interleaved schedules can benefit different outcomes (`SRC-0175`, `SRC-0176`). The literature does not justify one globally best schedule.

## Repetition needs a stop rule

Within-task research suggests fluency gains can continue over several repetitions but components change on different trajectories. Endless repetition wastes time and encourages memorization.

Candidate stop signals:
- improvement plateaus;
- target is already produced with low friction;
- verbatim repetition becomes dominant;
- speed improves without accuracy/meaning improvement;
- learner can pass a changed-content probe;
- opportunity cost exceeds expected gain.

Do not hard-code “repeat 5 times” as scientific truth.

## Beware massed-practice trade-offs

`SRC-0176` is especially important: intensive massed repetition improved some breakdown measures but degraded other speed/repair outcomes on a novel task.

Product implication:

```text
one fluency metric ↑
```

cannot authorize a training policy if:

```text
another meaningful dimension ↓
```

or transfer is absent.

The engine must watch for speed–accuracy–repair–meaning trade-offs.

## Spacing is useful, but no universal fluency lag exists

`SRC-0174` found comparable longer-term gains under 1-day and 7-day spacing in its particular training design. Existing RQ-004 evidence also rejects one universal interval for retention.

Therefore fluency scheduling should be adaptive/experimental:

```text
practice now
→ changed-content retry
→ spaced return
→ delayed transfer probe
```

not:

```text
fluency review always every 24h
```

## Formulaic sequences can reduce processing load—but can also become scripts

Multiword/chunk research (`SRC-0179`, `SRC-0180`, `SRC-0061`) supports teaching useful collocations/formulaic sequences, and their use is associated with several fluency dimensions.

For Nếp this supports high-value chunks such as:

```text
I'd like...
Could you...?
I don't understand.
What do you mean?
I'm looking for...
```

But the important fluency test is not reciting the chunk in one memorized sentence.

Evidence ladder:

```text
retrieve chunk
→ substitute slot
→ use with new lexical content
→ use in new scenario
→ respond with it in interaction
→ delayed spontaneous retrieval
```

Only later steps show flexible automatic availability.

## Speaking fluency dimensions

Candidate speech evidence:

### Speed
- articulation rate;
- speech rate;
- response initiation when interpretable.

### Breakdown
- mid-clause pauses;
- clause-boundary pauses;
- pause duration.

Mid-clause pausing can be especially informative about linguistic formulation, but exact interpretation is task/population dependent.

### Repair
- repetitions;
- reformulations;
- false starts.

Do not automatically reward fewer repairs. Some repair reflects useful monitoring; RQ-015 also treats interactional repair as a positive skill.

### Meaning/intelligibility guardrails
- task meaning fulfilled;
- listener understanding;
- target construction/lexis appropriate enough;
- pronunciation intelligible enough.

Temporal gains count only with guardrails intact.

## Interaction fluency is not monologue fluency

RQ-015 shows conversation adds:
- incoming-turn processing;
- response contingency;
- repair;
- turn coordination;
- partner behavior.

In dialogue, fast response is useful only if it is relevant and comprehensible.

Candidate evidence:

```text
contingent response
+ reasonable latency
+ low partner rescue
+ successful repair when needed
```

Do not pressure learners to answer instantly at the cost of understanding.

## Reading fluency

RQ-013 already established:

```text
reading rate
+ accuracy/comprehension
+ unseen-text transfer
```

must be kept together.

Repeated reading can help fluency, but practiced-text speed is not independent reading. Fluency review should eventually use unseen or changed connected text.

## Listening processing fluency

Listening needs real-time processing, but Nếp should avoid turning it into reflex tapping.

Candidate measures:
- comprehension on normal-speed input;
- reduced need for replay/transcript;
- ability to follow longer/less segmented input;
- faster correct action/response where the task naturally calls for one;
- successful next-turn response in interaction.

Do not simply impose shorter answer timers.

A learner who takes time to think after fully understanding audio is different from one who needed three replays to decode it.

## Writing fluency

RQ-014 records planning/writing/revision time, but typing speed is a major confound.

Writing automaticity should focus more on:
- faster retrieval of known language;
- fewer disruptive searches for basic forms;
- increased useful production under similar tasks;
- maintained message/accuracy;
- changed-task performance.

Never equate keyboard WPM with English fluency.

## Time pressure: use carefully

Procedures like 4/3/2 can reduce time available over repeated performances, but time pressure should only appear after the learner can already perform the task meaningfully.

Candidate progression:

```text
self-paced meaningful performance
→ repeat with modestly tighter time window
→ if meaning/accuracy collapses: back off
```

Time pressure is a practice manipulation, not a proficiency definition.

## Learner-effort evidence

Automaticity conceptually includes reduced processing cost. User-facing product measures should avoid intrusive cognitive testing every session, but research can observe proxies:
- latency trend;
- pause/hesitation trend;
- hint/replay/search use;
- stability across repeated/changing tasks;
- subjective effort sampled occasionally.

A useful state is:

```text
same quality
with less friction
```

not merely:

```text
more output per second
```

## Cross-modal transfer should not be assumed

DeKeyser's work shows practice can be skill-specific. Faster recognition does not automatically mean faster production; fluent reading does not prove fluent listening; monologue fluency does not prove dialogue fluency.

Therefore Nếp stores fluency/automaticity by **capability × modality × context** and only generalizes where cross-task evidence supports it.

## Proposed state

```ts
type FluencyEvidence = {
  capabilityId: string;
  modality: "listening" | "speaking" | "reading" | "writing" | "interaction";
  taskFamilyId: string;

  meaningSuccess?: number;
  accuracy?: number;
  intelligibility?: number;

  speed?: number;
  breakdown?: number;
  repair?: number;
  processingLatencyMs?: number;
  supportUse?: number;

  repetitionIndex: number;
  sameContent: boolean;
  noveltyLevel: number;
  delayed: boolean;
};
```

No single field should set `fluent = true`.

## Candidate fluency state levels

```text
F0 available only with substantial support
F1 accurate/meaningful but effortful
F2 easier on repeated familiar task
F3 efficient on changed-content same-function task
F4 efficient after delay across varied contexts
F5 efficient in less-controlled authentic interaction/input
```

These labels are product hypotheses, not CEFR replacements.

## Product decision

Create `FEAT-FLU-001` — **Adaptive fluency and automaticity orchestrator**.

It should:
- gate fluency practice on prior meaningful knowledge;
- use short bounded repetition;
- track repetition provenance;
- introduce variation after stabilization;
- combine spacing with changed-task probes;
- monitor speed/breakdown/repair without speed worship;
- preserve accuracy/meaning/intelligibility guardrails;
- treat formulaic language as reusable constructions, not scripts;
- keep fluency modality/task specific until transfer is demonstrated;
- require delayed novel/changed-task evidence before strong automaticity claims.

- whether subjective effort adds enough value to collect;

- mobile writing-fluency metrics that are not typing tests;
- formulaic-sequence flexibility threshold;
- how fluency evidence should influence review scheduling;
- exact delayed/changed-task criteria for calling language automatic enough for stage progression.
